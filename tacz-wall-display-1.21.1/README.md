# TACZ Wall Display 0.6.32

## 0.6.32：缓存开关与配置简中本地化（仅 1.21.1）

新增客户端配置 `cacheDecorativeGuns = true`，游戏内名称为“缓存装饰枪”，默认开启。开启时保留 0.6.31 的连接期跨维度缓存；关闭时在后续客户端处理帧清理一次已有缓存，此后切换维度时释放。当前场景仍保留正常渲染所必需的临时缓存，避免每帧重新捕获。重新开启不强制清理当前场景。

“缓存装饰枪”“最大渲染距离”“进入世界时显示摆放提示”均提供简中名称与鼠标悬浮说明，使用配置 spec 的 translation 键及 Configured 支持的 .tooltip 键；TOML 注释也为中文。缓存提示说明内存/显存占用、开启与关闭行为，以及退出连接/资源重载总会释放缓存。没有恢复预加载或保护机制，未修改存档、配置文件及依赖版本限制。1.20.1 本轮不变，仍为 0.6.31。

本轮构建及 49 项离线测试通过（零失败、零跳过）；未启动游戏，配置界面实际显示待人工验收。

## 0.6.31：取消预加载，使用连接期缓存（双版本）

本节为当前行为；下方 0.6.30 及更早条目仅为历史记录。

- 删除装饰枪预加载、范围扫描、清单握手、加载 UI 拦截、激活倒计时、玩家保护/冻结和临时网络禁火。正常游戏不再等待装饰枪准备完成；TaCZ/JEI 等其他模组自身的加载不受此改动影响。
- 删除 `preloadMode`、`preloadTimeoutSeconds`、`preloadRadiusChunks` 及与严格保留冲突的 `modelCacheVertexLimit`、`dimensionCacheVertexLimit` 定义。客户端设置仅保留显示距离、入世提示；部署不编辑已有配置文件。
- 只在实际渲染请求后捕获模型；保留每帧队列及最多三次失败尝试。普通枪、Mesh、配件、六面摆放、旋转、翻转、Create 移动结构继续使用现有捕获算法。
- 同一连接中，CPU 模型与静态/移动 GPU 缓冲不因跨维度、区块卸载或空闲时间淘汰；相同快照/光照复用。位置和姿态以当前方块为准，不缓存旧世界对象，不绘制已移除/替换的方块。
- 退出存档/服务器或资源重载时释放缓存。首次见到新外观、出现新光照组合或资源重载后仍需准备；不能承诺所有帧零卡顿。单次 Mesh 捕获性能优化仍不在本轮范围。
- 严格连接期保留会随不同外观/光照组合增多而增加内存与显存占用。统一使用已有局部空间绘制路径，密集场景 draw calls 可能多于旧加载批次；未做实机性能测量。
- 跨维度仍自动关闭摆放模式并显示聊天/音效提示，已改为独立网络消息。摆放协议为 `2`，客户端及服务器需同时更新。
- `/wallgun_stats` 显示模型、GPU 缓冲、顶点、捕获、上传、失败和队列计数；跨维度日志记录保留量。没有改变存档格式、原枪数据或依赖版本约束。

验证记录见 [0.6.31 验证说明](../VERIFICATION-0.6.31.md)。


## 0.6.30：修复预加载预算提前耗尽（两版同步）

修正 0.6.29 将入世初始化/握手耗时计入 10 秒准备预算的回归。完整激活从进入加载起计时，60 秒安全兜底不变；附近区块检查与模型准备的预算从第一次有效握手开始，重复 offer 和清单修订均不续期。握手等待不再设置“玩家已离开加载界面”标记。

半径仍默认为 2。暂未加载或尚未订阅的目标区块保持待检查，在预算内重查；不会强载或生成区块。只有所有候选区块检查完成才封口清单，空清单与超时降级分别记录。真实离开加载界面仍立即申请安全恢复；不把已接管操作的玩家拉回加载界面。日志增加握手耗时、准备耗时、未检查数量和准备完成结果。

协议 `activation-7`，客户端及服务端须同时更新。新增慢握手、重复握手、迟到区块、未知区块不算空场景等离线回归；未启动游戏，冷缓存入世/跨维度与游戏内渲染仍须人工验收。单次 Mesh 捕获性能优化不在范围，存档、枪包和配置不作部署写入。下方 0.6.29 计时/未知区块跳过说明为历史行为，已由本节修正。


## 0.6.29：附近区块准备与失败降级（两版同步）

离线验证：两版各 64 项测试，包含半径边界、有限重试、渲染入口不直接捕获、握手不重置计时和四把真实 Mesh 模型。1.21.1 实例原测试枪包缺失，使用 `-PmeshTestPack=E:/GAME/Minecraft/Minecraft 1.20.1/.minecraft/tacz/duyupack+1.21.1.zip` 只读补跑。ForgeGradle 首次环境 HTTPS 检查停顿，终止本次构建后设置 10 秒连接/读取时限重试；未关闭证书校验。跳过装饰枪准备不强行关闭原版地形加载界面。

客户端配置 `preloadRadiusChunks = 2`，范围为玩家目标区块周围 5×5（25）个区块，允许 0–8；0 仅检查所在区块。服务端只读取已加载且已订阅的区块，不强载、不生成、不等待未知区块；清单只包含装饰枪区块。空清单不等待世界区块编译；附近已同步的 Create 移动装饰枪保留准备支持。未同步或范围外对象以后按需处理。

`preloadTimeoutSeconds = 10` 不变，从进入本次加载开始计时，新 offer 不重置。完整激活仍有 60 秒安全降级；清单过大、反复变化及模型失败转入跳过请求，不因这些准备问题断线。服务端收到可响应客户端的跳过/恢复确认后先解除保护，再恢复客户端控制；不对完全失去响应的客户端盲目解除保护。无 offer 时定期查询并申请跳过；ready 与释放回复可重发。协议升为 `activation-6`，服务器及客户端需一起更新。

正常游戏使用现有静态缓存的帧预算队列，包括 OFF 模式和 Create；失败模型延迟 2 秒、10 秒各重试一次（总共最多三次尝试），仍失败则保留缺失标记，资源重载可重试。旧世界队列随世界切换清理。未改变存档、枪械/配件/Mesh 捕获算法、旋转翻面、摆放禁火、持枪初始化及 JEI/TaCZ 联动。

每 5 秒记录等待阶段、会话/维度/代次、区块数量、模型及批次数；扫描和释放记录摘要，捕获开始记录枪 ID 与外观标识，已有完成/异常日志保留。加载界面显示真实阶段。诊断日志需同时收集客户端与服务端，并记录传送时间和坐标；玩家提供的旧日志不能单独证明末地卡住的具体根因。

单次 Mesh 捕获性能优化不在本次范围；帧预算不能打断正在执行的第三方模型加载或 GPU 调用，也不能消除 JEI 主线程阻塞。本轮不启动游戏，实际多人末地往返、延迟/丢包与画面回归需人工验收。


## 0.6.28：Mesh 模型静态捕获兼容

存档格式不变，已有装饰枪保留 OriginalGun 和摆放姿态；更新后重启客户端重新生成缓存，无需拆除重摆。静态墙面、局部编辑及 Create 移动结构继续使用统一网格。没有修改玩家存档、枪包或其他模组；1.20.1 未同步。

本轮未启动客户端。待实机验收：当前存档四支旧枪原位恢复，配件/透明/发光/光影，六面旋转翻面，Create 移动与拆卸，重载及跨维度，以及未装 Mesh Loader 时的运行时可选加载。发布不应表述为这些实机项目均已通过。

## 0.6.27：入世持枪初始化修复（两版同步）

加载期间不再把 TaCZ 时间同步和握手消息当作战斗包丢弃，当前快捷栏槽位同步也正常通过。拔枪请求合并为一次待办，在服务端恢复控制前根据最终选中槽位补办；缺失首次持枪状态时也会修复。客户端配对重建拔枪动画及正常冷却，但不重复发送拔枪包。射击、近战等加载期间请求不会延迟重放。修复“初入世界仅有开火表现、切枪才恢复”的已识别初始化丢失路径。

1.20.1 同步本节以及 0.6.26 的保护会话收尾、命令死亡放行和可关闭入世提示。两版协议统一为 `activation-5`，客户端和服务器须一起更新；10 秒可配置预加载预算、60 秒安全跳过、枪械数据及摆放禁火机制不变。测试与部署边界见 [0.6.27 验证记录](../VERIFICATION-0.6.27.md)。

## 0.6.26：保护会话收尾与入世提示

仅更新 1.21.1。取消或同维度传送不再建立跨维度保护；客户端离开加载界面后立即请求跳过预加载，服务端先移除保护再确认恢复，迟到的 offer 不会重新开启客户端加载状态。加入会话编号／加载代次校验、释放回复重发、无会话状态查询及断线清理，避免旧会话干扰新的加载。管理员 `/kill` 的专用伤害可结束保护并按原版处理。60 秒安全跳过、默认 10 秒预加载限时不变，未响应客户端仍不会被直接暴露给环境伤害。本轮不修改 TaCZ–JEI 联动。

每次连接存档或服务器，完成加载后在本地聊天显示一次摆放模式说明，使用当前绑定键；重生及切维度不重复，未绑定时提示到控制设置绑定。包含摆放模式禁火提醒。可在 `config/tacz_wall_display-client.toml` 设置 `showPlacementHintOnJoin = false` 关闭。

协议为 `activation-4`，客户端与服务器必须同时更新。离线验证与实机待测边界见 [0.6.26 验证记录](../VERIFICATION-0.6.26.md)。

## 0.6.25：激活超时安全跳过

入世或切维度时，装饰枪激活等待达到 60 秒后改为安全跳过预加载，不再因该计时器强制断线。客户端尚未回应时，服务端继续保护玩家；收到客户端偏好或跳过请求后，才发送释放通知并恢复游戏。TaCZ–JEI 自身的加载时间不受影响。双端握手协议为 `activation-3`，客户端与服务端须同时更新。下方旧版本的 300 秒断线说明仅为历史记录。

## 0.6.24：解除 TaCZ 版本门禁

1.21.1 版仍要求客户端和服务端安装非官方 TaCZ NeoForge Port，但不再因 TaCZ 版本不是 r6 而由加载元数据直接拒载。构建仍以 r6 为基线；r7 的启动、渲染与交互兼容性尚待人工验证，解除门禁不代表已验证或保证兼容。1.20.1 版不变。

## 0.6.23：可配置的预加载超时

`LOADING` 模式的初始场景预加载限时现在由客户端配置 `preloadTimeoutSeconds` 控制，默认 10 秒（范围 1–240 秒）；超时后请求服务端安全跳过本次预加载，收到释放确认后才恢复游戏。客户端已发送准备完成通知、等待服务端确认时不会误触发预加载超时。此处 300 秒截止时间为 0.6.23 的历史行为，当前规则以上方 0.6.25 说明为准。

## 0.6.22：修复多枪包环境下无法进入世界

入世和切维度时，服务端会重发未确认的激活请求，客户端会等待目标维度就绪后处理，并正确处理重复请求。`OFF` 完全跳过装饰枪预加载及其模型失败判定；`LOADING` 遇到模型失败或预加载超过 90 秒时，客户端请求服务端跳过本次预加载，收到释放确认后才恢复游戏。整个等待会话最多 300 秒，超出仍会断开以保持玩家冻结保护。此版握手协议已升级，客户端与服务端都必须更新。验证记录见 [0.6.22 验证说明](VERIFICATION-0.6.22.md)。

## 0.6.21：跨维度自动退出摆放模式

玩家在摆放模式下成功进入其他维度时，服务端会关闭该模式；新维度加载完成、恢复控制前，客户端复用手动关闭时的聊天信息和关闭音效。登录、同维度重生及取消的维度传送不会触发自动关闭。测试与部署记录见 [0.6.21 验证说明](VERIFICATION-0.6.21.md)。

## 0.6.20：取消摆放后的延迟批次合并

修复上一版停止编辑 750 ms 后仍在渲染线程重建整组模型的问题。运行期间放置、旋转或移除影响的单元持续复用局部网格，接管后释放旧静态批次，不再在空闲时重新合并。初始场景仍使用静态批次；编辑单元会增加绘制调用，共享几何缓存避免相同模型逐枪复制。测试范围、数据和边界见 [0.6.20 验证说明](VERIFICATION-0.6.20.md)。

## 0.6.17：加载阶段准备与服务端激活

集合范围、资源上限、兼容边界、隔离服务器测试及部署记录见 [0.6.17 验证说明](VERIFICATION-0.6.17.md)。本节及以下旧版本条目为历史记录，当前行为以上方最新版本说明为准。
## 0.6.0：自由摆放与装饰枪交互

默认 P 键位于原版控制设置的 TACZ 分类，不再由 config 设置。模式内左键按原版规则破坏方块，装饰枪为零硬度，生存空手单击即可拆除并取回原枪。手持真枪右键方块可放置装饰枪；指向已有装饰枪时，任意主手物品或空手右键旋转 22.5°，左 Alt＋滚轮翻面。持真枪左 Alt＋右键已有装饰枪时，按点击面的原版邻格规则再放一支，可悬于墙外。木棍和调整工具配置不再参与这些操作。

右上角提示框显示上述操作和当前绑定键位，宽度不超过屏幕三分之一，背景 50% 透明；橙色屏幕边缘在四角连续。成功放置使用石头／圆石放置音效；模式开关复现整合包 ExtraSounds 开关物品栏的原版 toast 音源，无须安装 ExtraSounds。

## 0.5.0：手持真枪自由摆放

默认按 P 进入／退出枪械自由摆放模式（可在控制设置改键，客户端 `config/tacz-wall-display-client.toml` 的 `toggleKey` 设置初始默认键）。模式下手持 TACZ 真枪右键可直接放出保留全部枪械数据的装饰枪，左键按原版空手方式破坏方块；TACZ 枪械操作暂时停用，退出即恢复。右上角说明框按当前语言和实际键名自适应宽度，右端固定，文字不换行；屏幕边缘显示橙色模式提示。生存放置消耗真枪，拆除返还同一枪；创造放置及拆除沿用创造模式规则。

旧版双向合成已经关闭。旧装饰枪物品注册仍用于存档迁移，标准物品 NBT 读取时还原原枪；玩家背包、末影箱、掉落物和打开的容器另有补充检查。旧装饰枪物品不能再次直接放置，中键选取现有装饰枪会得到原枪。第三方模组的非标准存储格式需另行验证。1.20.1 本轮不更新。

## 0.4.8：机械动力强力胶与旋转结构

在 1.21.1 安装 Create 6.0.10 时，强力胶可以把装饰枪连同支撑方块收进机械轴承等移动结构；枪械随结构旋转，拆卸后恢复原方块及保存的真枪数据。Create 是可选兼容，不安装时原有静态展示功能照常运行。本轮不更新 1.20.1。

静态墙面继续使用原有批量绘制。移动结构单独复用 TACZ 静态捕获的枪械网格，GPU 缓冲按枪械及摆放姿态缓存，并套用 Create 的移动矩阵；不会每帧重新捕获 TACZ 模型。新增模型捕获及上传按帧排队，移动缓存最多保留约 800 万顶点。客户端同步的枪械信息使用压缩表示，服务端和存档中仍保存完整原枪；旧存档中的非压缩数据可继续读取。

`/wallgun_stats` 新增 `movingVirtualCalls`、`movingDraws`、`movingUploads`、`movingCachedVertices`、`movingPending`、`movingCpuMs`、`peakMovingCpuMs`。CPU 指标是移动枪械绘制调用的单帧耗时，不包含 Create 其他方块、着色器或 GPU 完成时间。测试时先记录静止帧，再启动、停机、重新启动结构，比较首次上传与稳定旋转阶段；若 `movingUploads` 在稳定阶段持续增加，或 `movingPending` 长期不归零，应收集该命令结果和帧时间曲线。

隔离测试使用 Create 6.0.10、TACZ 1.1.8-hotfix-r6：40 支和 160 支同型号、带配件装饰枪均实际被强力胶收集、客户端随轴承旋转绘制，停机后全部还原；同一模型只捕获和上传一次。160 支同模型测试的移动绘制 CPU 耗时约 1.8 ms/帧，峰值约 9.1 ms。该数值仅覆盖隔离客户端的一种枪型，不代表不同枪包、着色器或完整整合包下的帧率保证。另在不安装 Create 的隔离客户端完成原有六面调整测试。
## 0.4.7：按展示面切换旋转方向

调整物品（默认木棍）右键：默认面每次逆时针旋转 22.5°，Shift 翻面后每次顺时针旋转 22.5°；再次翻回恢复逆时针。继续按玩家观察侧适配六面放置，Shift 翻面及单次音效不变。已有摆放姿态不变，下次交互使用新规则。

## 0.4.6：WTHIT 显示枪械本名

安装 WTHIT 时，指向装饰枪会显示所保存原枪的本名，不再显示“装饰枪”前缀；保留 WTHIT 的图标、名称格式和模组来源行。名称随客户端语言切换，不采用铁砧自定义名称。WTHIT 为可选兼容，不增加必需前置。只更新 1.21.1。

## 0.4.5：静态装饰只显示当前安装的弹匣

修复新建独立枪械模型时未执行 TACZ 动画状态清理，导致换弹用 `additional_magazine` 与正常弹匣同时被捕获的问题。静态捕获前仅对独立模型恢复正常状态，再应用已有的枪包显隐修正；标准与扩容弹匣继续由 TACZ 按保存的原枪配件选择。不会启动逐帧动画，也不改变真枪数据或玩家手持模型。

重启游戏后，已有装饰枪会重新生成正确缓存，无需拆除或重新合成。仅更新 1.21.1；1.20.1 保持原版本。

N4 专项测试：`gradlew --offline test build -Psmoke smokeJar`，独立测试实例使用 `-Dwallgun.magazineSmoke=true`。`-Dwallgun.magazineSeedOld=true` 配合旧版正式 JAR 复现重叠并保存测试存档，替换为新版后使用 `-Dwallgun.magazineReopen=true` 验证旧存档升级和重新进档。需要本机 Suffuse 与 Spearhead 枪包；只在隔离测试实例中运行。

## 0.4.2：装饰枪始终捕获高精度模型

修复部分瞄具在首次静态捕获时选到 TACZ 低模、随后被缓存的问题。仅在 `MeshCapture` 生效期间覆盖 TACZ 的高模距离判断；由 TACZ 同时选择高模及对应贴图。继续使用静态 `FIXED` 捕获，不运行第一人称瞄准渲染，不改写 TACZ 配置。正常真枪渲染仍遵循 TACZ 的原有距离判断。

升级后重启游戏即可让已有装饰枪重新生成模型缓存，无需重新合成、破坏重放或迁移存档数据。

本轮验证：13 项单元测试通过；使用实际发布 JAR，在独立正式客户端中测试 EXP3、ACOG TA31、Elcan 4× 三种瞄具。按 TACZ 距离设置 0 → 8 → 9999 分别清空缓存后捕获，三组模型的顶点、材质、贴图及全部顶点属性完全一致，均无 LOD 贴图。另验证捕获前后普通 TACZ 远距离判断不变、静态缓存复用，以及设置为 0 时三支已装配装饰枪正常摆放渲染。此次未重做大规模帧率基准测试。

复现回归：`gradlew --offline test build -Psmoke smokeJar` 生成正式 JAR 及独立测试 JAR；在隔离实例中搭配对应 TACZ，以 JVM 参数 `-Dwallgun.lodSmoke=true` 启动，结果写入 `lod-verification/SUCCESS.txt` 和截图。测试 JAR 仅用于隔离实例，不能随正式模组部署。开发环境也支持 `gradlew --offline -Psmoke -PlodSmoke runClient`。

## 前置与发布说明

唯一需要另行安装的模组前置是对应版本的 TACZ；本模组和 TACZ 都需要装在客户端及服务端。Forge／NeoForge 的版本号只作推荐，本附属模组不再按平台版本号阻止加载。

硬性限制：Minecraft `[1.21.1]`、必须安装 TaCZ，且必须使用 NeoForge；本模组不限制 TaCZ 版本号。NeoForge **21.1.248 仅为推荐版本**，不是最低版本。使用 Java 21。TaCZ 必须来自 **[UNOFFICIAL] TaCZ NeoForge Port**，不是官方 Forge 版。

平台依赖与 `loaderVersion` 使用 `[0,)`，取消本模组施加的平台版本门槛；TACZ 或整合包内其他模组的要求仍由它们自己决定。低版本验证边界见下方依赖评估，不宣称所有历史版本都兼容。

静态捕获 Mixin 调用了 TaCZ 内部渲染接口；r6 是编译基线，其他版本仍须实测。TaCZ 自带 SimpleBedrockModel 等库，无需单独安装 GeckoLib。Cloth Config、Sodium／Embeddium、Iris、RuOK、Packet Fixer 均不是本附属模组的硬性前置；枪包自身的依赖由枪包决定。

可直接复制的英文页面见 [CurseForge 说明](CURSEFORGE.md)，依赖审查依据及分文件发布关系见 [依赖评估](DEPENDENCIES.md)。

## 使用

- 默认按 P 进入自由摆放模式；手持真枪右键目标方块，直接将该枪摆成装饰枪。再次按 P 退出，可在原版控制设置的 TACZ 分类改键。
- 支持东、西、南、北、上、下六面放置。可以借助临时方块定位，再拆除支撑，装饰枪会保留。
- 装饰枪零硬度，生存空手单击即可拆除，掉落原枪并保留配件、弹药、名字及其他组件；创造模式沿用默认无掉落行为。
- 模式内任意主手物品或空手右键装饰枪：旋转 22.5°；左 Alt＋滚轮装饰枪：水平翻面。
- 模式内持真枪左 Alt＋右键装饰枪：在被点击面的邻格放置，不要求支撑方块。
- 每次成功调整播放一次展示框放入物品音效。地面／顶面的初始方向随放置者朝向确定；后续翻面保持这个基准。
- 摆放方向保存在方块实体中并同步给客户端；拿回真枪后再次放置，重新使用默认方向。
- 默认视觉方向为尾部左、枪口右。现有 0.2.x 通用装饰枪方块重启后使用新默认外观，原枪数据不受影响。

## 外观与性能

直接读取 TACZ 和枪包原有贴图、模型、配件外观。模型仅首次捕获为静态网格，之后按材质及固定空间小单元批量绘制。转动与翻面只改变摆放变换，不重新捕获枪械模型。

进入世界、重生或跨维度时，在原版加载界面内准备服务端明确发送的有限集合；等待结束以服务端匹配会话的恢复通知为准。模型、GPU 上传与首次材质绘制都参与完成判定。详细范围与失败处理见 0.6.17 验证说明。

随版本提供本机 560 个已加载条目的朝向审查结果，其中 220 个枪械条目需要转换默认展示侧。558 个有效外观 ID 的校准信息位于 `assets/tacz_wall_display/orientation.json`；这是方向元数据，不是预设方块注册表。新增外观优先以枪口定位节点作自动判断，也可通过资源包覆盖校准文件。

静态装饰保留激光器本体，跳过 TACZ 实时瞄准射线；另对 `ccrp:hk416_sopmod` 模型中名为 `laser_illuminated` 的静态长射线辅助骨骼作局部隐藏，不修改枪包或真实持枪渲染。

审查边界：`bf1:handgun` 是源枪包固定展示缩放为零、包含手部模型的特殊条目，没有可审查的枪械展示几何；保留缺失标记和原枪数据。`bf1:lunge_mine`、`bf1:syringe`、`ccrp:shield_ots33` 为突刺地雷、注射器和盾牌类特殊外观，不适用枪托／枪口规则，保留源展示侧。未来新增或重做的枪包仍可能需要视觉校准。

## 开发验证

`gradlew test build`：产品构建与单元测试。

`gradlew -Psmoke -PplacementSmoke runClient`：隔离客户端测试合成关闭、旧物品迁移、六面直接放置、生存消耗、创造中键、P 键输入屏蔽及客户端右键网络放置。

加载协议使用独立服务器测试：先执行 `gradlew -PactivationSmoke runActivationServer`，再执行 `gradlew -PactivationSmoke runActivationClient`。原 0.6.16 的 warmupSmoke 非阻塞断言已停用；测试配置和失败场景见最新验证说明。

`gradlew -Psmoke -Paudit runClient`：生成全部已加载枪械的编号预览和清单。`-PauditOnly=namespace:id,...` 可定向复核。

测试源集不进入发布 JAR。各测试只使用 `run-client` 内的新存档或独立副本；不编辑玩家存档。

装饰枪兼容性专项回归：独立测试 JAR 配合 JVM 参数 `-Dwallgun.compatibilitySmoke=true`，默认以 TACZ 自带 HK416 与 SCAR-L 检查四档弹匣静态模型、双向合成、原枪掉落和挂墙渲染。可用 `-Dwallgun.compatibilityGuns=namespace:first,namespace:second` 指定两个支持测试配件的原枪 ID。结果写入 `display-compatibility-verification`；不验证真枪射击、换弹或枪包配方。历史清理说明见根目录 `migration/HISTORY-CLEANUP.md`。
