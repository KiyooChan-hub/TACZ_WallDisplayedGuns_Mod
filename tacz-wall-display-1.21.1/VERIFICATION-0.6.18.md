# 0.6.18 加载耗时修复与部署验收（2026-09-29）

## 修改
- 服务端取消每 tick 固定 8 区块限制，初次扫描与最终复核均按每会话每 tick 4 ms 软预算推进。单次描述不可抢占，极复杂单区块可能超预算。
- 使用 getChunkNow 非阻塞查询；未生成或尚未发送的区块轮转到末尾，避免队首阻塞。
- 客户端收到部分清单即开始模型/GPU 准备，与后续地形传输重叠；必须完整封口、模型及 GPU 就绪、服务端复核通过才激活。
- 区块描述按不可变枪快照、姿态、方块状态和位置缓存，状态相同不再反复编码物品 NBT。线程独立弱键缓存避免跨线程共享与长期持有卸载区块。
- 补全尚未实例化的装饰枪方块实体，避免漏报存档里的枪。
- GPU 维度缓存超预算时逐批释放，保留能容纳的部分；加载期间暂停恢复缓存的十秒过期计时。
- 保留原协议、120 秒失败关闭、玩家保护、完整范围与最终一致性复核。此版采用状态签名缓存降低全量核对成本，未改为区块 dirty revision 协议；场景变化仍按原流程刷新清单。

### 服务端 arm 到 release 耗时
| 场景 | 39 型/100 枪、默认 200 万顶点缓存 | 同场景、10 万顶点缓存 |
| --- | ---: | ---: |
| 首次进入 | 4.181 s | 4.183 s |
| 空地狱 | 2.163 s | 2.310 s |
| 返回枪墙 | 1.298 s | 1.297 s |
| 重生 | 1.598 s | 1.600 s |

默认缓存返回命中 100 批；10 万顶点预算仍命中 8 批，其余正常重建。两轮模型失败数均为 0。最终预算测试五次累计 216 tick 玩家保护检查通过。未在本轮复测独立观察者、多客户端、OFF 和 120 秒超时用例。

旧实现 1469 个区块两遍扫描即有约 18.4 s 固定下限；用户正式日志返回场景约 19.2 s。本轮测试不是同一正式存档 A/B，不能据此承诺正式存档固定加速倍数。首次新地形生成、网络传输、光影编译仍可能增加实际等待时间。首轮旧阻塞查询曾导致新地狱约 27.9 s；改为非阻塞查询后未重新生成同规模全新地狱，后续地狱数据已生成。
