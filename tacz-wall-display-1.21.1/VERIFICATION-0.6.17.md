# 0.6.17 加载会话与玩家激活

默认维护 Minecraft 1.21.1 / NeoForge；不更新 1.20.1。

## 行为和协议

- `LOADING` 取代 `BACKGROUND`。登录、重生、跨维度的原版地形界面等待客户端准备与服务端匹配会话的恢复通知；不新增装饰枪进度界面。`OFF` 主动跳过准备，仍保留原版地形就绪判定。
- 客户端与服务器都必须安装新版本。必需的 `activation-1` 网络通道会拒绝不兼容旧端，不静默退化为客户端等待。
- 服务端在登录入口、重生新实例恢复入口、维度切换入口建立等待；会话绑定玩家实例、连接和维度。旧确认、旧修订不放行。取消的维度旅行也会对留在原地的玩家重新完成安全握手。
- 等待时暂停玩家 tick/doTick、客户端预测运动，拒绝原版玩法包和 TACZ 玩法自定义包，拦截普通伤害、目标选择、推动及 move 物理位移。连接保活、传送确认、区块批次确认及数据发送照常执行，世界与其他玩家照常推进。
- 释放前同步服务端位置，清空速度和跌落距离；等待时清空悬空检测计数。挂起机制不改写玩家的永久无敌或游戏模式。

## 有限集合

初始集合是本次服务端区块订阅视图中、以目标玩家位置为中心、且落在客户端有效渲染距离与模组展示距离对应区块半径内的静态装饰枪；半径上限 32 区块。仅使用已经加载并由原版发送的区块，不增加强制区块票据。

服务端每 tick 最多处理 8 个区块；逐块发送确定的原枪组件、位置、朝向、姿态，最后明确封口。客户端核对实际收到的区块／方块实体，捕获缺失模型、上传 GPU 批次并完成真实世界材质通道中的首次绘制。服务端在确认后再次分批核对集合；加载期间内容改变会增加修订并重新确认，最多 8 次重试。

每区块最多 256 支枪、描述最多 512 KiB；每会话描述累计最多 32 MiB。超限、失败或 120 秒截止会明确断开连接，绝不超时放行。确认扫描之后的新增、远处后续区块和正常探索不属于已封口集合的保证。

已收到的 Create 移动结构额外发现模型、准备缓冲并进行首次材质绘制；晚到的移动实体不属于静态区块集合的送达保证。模型缓存和维度 GPU 缓存继续复用、核对与失效。加载时允许活动移动缓存超过预算，避免预热期间反复淘汰；离开维度和资源重载会释放，后续新缓冲入队继续执行原有回收。

## 边界

- 本机制覆盖原版与已接入 TACZ 的入口；其他模组直接设置生命值、独立计时或独立移动玩家的代码不保证被完全隔离。骑乘和整合包自定义传送／反作弊仍需具体整合验证。
- 资源重载会清除缓存；在正常游玩时手动重载资源并不创建新的服务端等待会话。后续区域和新枪的运行时准备仍可能造成帧时间峰值。
- OFF 的首次观察允许卡顿。旧 BACKGROUND 配置由新枚举默认值纠正为 LOADING；部署时显式迁移这一项，并保留其他设置。

## 验证方式

单元测试：`gradlew --offline test`。
独立服务器：`gradlew --offline -PactivationSmoke runActivationServer`。
隔离客户端：`gradlew --offline -PactivationSmoke runActivationClient`。
第二玩家：`gradlew --offline -PactivationSmoke runActivationObserver`。
双方增加 `-PactivationScenario=timeout` 或 `failure` 验证失败关闭。

测试专用源集不进入产品 JAR；服务器只监听 127.0.0.1:25586。运行前应在对应隔离目录准备 server.properties/eula.txt 与 options.txt：音乐 0、总音量 0.5、其他分类 1.0。不要指向玩家存档。每次结果应结合最新日志和文件修改时间，避免误读旧成功标记。

## 本轮实际结果（2026-09-29）

- `test build` 成功，29 项 JUnit，0 失败、0 错误；`-Psmoke compileSmokeJava` 成功。JAR 检查不包含专项测试类。

- 客户端故意延迟会话处理约 3 秒，并发送旧会话确认；每次放行前检查模型队列和已完成首次绘制的 GPU 批次。最终候选通过 415 次等待期间普通伤害、目标与推动保护检查。最终截图显示枪墙及完整生命值。
